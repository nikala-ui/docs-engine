Nikala Docs Engine loads a TypeScript configuration file from the project
root. The preferred filename is `docs.config.ts`:

```ts
import type { DocsConfig } from "@nikala-ui/docs";

const config: DocsConfig = {
  title: "Project Documentation",
  description: "Documentation for my project.",
  contentDir: "docs",
  favicon: "/favicon.ico",
};

export default config;
```

The loader also accepts `docs.config.js`, `docs.config.mjs`,
`nikala.docs.config.ts`, `nikala.docs.config.js`, and
`nikala.docs.config.mjs`. Older projects may use `nikala.config.ts` or
`nikala.config.js`.

Configuration values are merged with the engine defaults. Nested `theme`,
`navigation.sidebar`, `shiki`, and `search` values are merged as well.

## Site metadata

```ts
export default {
  title: "Project Documentation",
  description: "Reference and guides for the project.",
  siteUrl: "https://docs.example.com",
  favicon: "/favicon.ico",
  contentDir: "docs",
  css: "src/index.css",
};
```

- `title` is used in the navbar and browser titles.
- `description` is the fallback description for pages without frontmatter.
- `siteUrl` enables canonical URLs in the generated HTML.
- `favicon` sets the favicon path or URL.
- `contentDir` selects the directory containing MDX pages. The default is
  `docs`.
- `css` points to a consumer-owned CSS entrypoint that should be included in
  the site build.

## Home page layout

The root page is `docs/index.mdx`. Use `home` to choose between the normal
documentation layout and a landing page:

```ts
export default {
  home: {
    layout: "landing",
    showSidebar: false,
    showNavbar: true,
    showBreadcrumbs: false,
    showToc: false,
    showPager: false,
  },
};
```

For the normal documentation layout, omit `home` or set
`layout: "docs"`. On a landing page, sidebar, breadcrumbs, table of
contents, and pager visibility are controlled independently by the matching
`show*` values.

## Logo, repository, and top navigation

```ts
export default {
  logo: {
    text: "Project Docs",
    image: "/logo.svg",
    href: "/",
  },
  repository: {
    url: "https://github.com/example/project",
    branch: "main",
    rootDir: "",
  },
  nav: [
    { title: "Home", href: "/" },
    { title: "API", href: "/api" },
    { title: "Source", href: "https://github.com/example/project", external: true },
  ],
};
```

`logo.image` is served from the consumer project's public assets. Set
`external: true` for links that should open in a new tab.

When `repository` is configured, the default theme adds a `View source` link
to each documentation page. The link is built from the repository URL, branch,
`rootDir`, and the page's path under `contentDir`.

`branch` defaults to `main`. Set `rootDir` when the documentation project is
nested inside the repository, for example `"apps/docs"`; the configured
`contentDir` is appended automatically. GitHub, GitLab, and Bitbucket source
URL formats are supported.

Page copy actions are enabled in the default theme. `Copy as Markdown` uses the
page's original MDX source, without the rendered navigation or component
controls. Add AI providers with URL and prompt templates when needed. The
`{url}`, `{content}`, and `{title}` placeholders are available in prompts and
are URL-encoded when inserted into an action URL:

```ts
export default {
  pageActions: {
    copyPage: true,
    copyMarkdown: true,
    ai: [
      {
        name: "ChatGPT",
        url: "https://chatgpt.com/?q={prompt}",
        prompt: "You are my documentation companion. I’m reading ‘{title}’ at {url}. Teach me how to use this page in a practical way: explain the core idea, show an idiomatic example, point out common mistakes, and help debug problems using the documented APIs and conventions.",
      },
      {
        name: "Claude",
        url: "https://claude.ai/new?q={prompt}",
        prompt: "You are my documentation companion. I’m reading ‘{title}’ at {url}. Teach me how to use this page in a practical way: explain the core idea, show an idiomatic example, point out common mistakes, and help debug problems using the documented APIs and conventions.",
      },
      {
        name: "v0",
        url: "https://v0.dev/chat?q={prompt}",
        prompt: "You are my documentation companion. I’m reading ‘{title}’ at {url}. Teach me how to use this page in a practical way: explain the core idea, show an idiomatic example, point out common mistakes, and help debug problems using the documented APIs and conventions.",
      },
    ],
  },
};
```

## Sidebar and navigation layout

The default layout is the sidebar layout:

```ts
export default {
  navigation: {
    layout: "sidebar",
    sidebar: {
      header: true,
      footer: false,
      headerSubtitle: "Developer Documentation",
      footerText: "Project Docs",
    },
  },
};
```

Set `layout: "top"` to place navigation above the content without the
desktop sidebar. The automatic sidebar is built from the `docs/` directory;
directories become categories and page frontmatter controls ordering.

For page-level navigation metadata, use:

```mdx
---
title: Installation
order: 1
categoryOrder: 1
icon: package
badge: New
toc: true
prev: /getting-started
next: /configuration
---
```

## Theme and CSS

The default theme uses the packaged theme unless a local theme path is
configured:

```ts
export default {
  theme: {
    path: "./src/themes/default",
    defaultMode: "system",
  },
};
```

`theme.defaultMode` sets the initial color mode when the visitor has not
chosen a preference yet:

```ts
// docs.config.ts
export default {
  theme: {
    defaultMode: "dark",
  },
};
```

Use `"light"`, `"dark"`, or `"system"`. A mode already saved by the visitor
in local storage takes precedence over this default.

Page icons use Lucide Icons in the default theme. Pages without an `icon`
metadata field render without a page icon. Additional icon systems may be
supported by future theme releases.

Use `css` to add a consumer-owned Tailwind CSS entrypoint. Keep custom colors
and layout values in semantic design tokens rather than hardcoding them in
theme components.

## Syntax highlighting

Shiki themes can be selected independently for light and dark mode:

```ts
export default {
  shiki: {
    themes: {
      light: "github-light",
      dark: "github-dark",
    },
    langs: ["typescript", "tsx", "javascript", "jsx", "json", "css"],
  },
};
```

Only languages listed in `shiki.langs` are enabled for highlighting. They are
loaded on demand, while unsupported or unlisted languages safely render as
plain text. Keep the list limited to the formats used by the documentation
site so production bundles stay small.

## Search

Local search is enabled by default and is the built-in provider:

```ts
export default {
  search: {
    enabled: true,
    provider: "local",
  },
};
```

Set `enabled: false` to remove the search trigger from the default theme.
The default theme currently implements `local`. If `pagefind`, `orama`, or
`algolia` is selected before a corresponding integration is installed, the
engine safely falls back to local search instead of rendering a broken search
dialog. Those providers are reserved for future index adapters.

## Environment-specific configuration

The configuration is loaded from the current project root. Keep site-specific
values in `docs.config.ts` and avoid hardcoding paths or branding in engine
source. When changing configuration during development, restart the server
if a value is not picked up by the watcher.
